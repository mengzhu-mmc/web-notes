# 02-二、渲染性能 - 标准答案索引

> 来源：[[02-二、渲染性能]]。本页沉淀可直接用于面试表达的答案。

## 回答结构

- **结论**：先直接回答核心问题。
- **原理**：解释关键机制，不只背定义。
- **实践**：结合项目落地、指标或复杂度说明。
- **追问**：主动暴露可深入的方向。

## 高频标准答案

### Q1：如何排查页面卡顿？

先用 Performance 录制定位长任务、频繁 layout、paint 或脚本执行热点；再结合 React Profiler 或业务埋点看具体组件和交互。优化时按减少计算、减少 DOM 变更、拆分长任务、降低渲染面积的顺序处理。

**关键词**：Performance、Long Task、Profiler、渲染面积

**追问方向**：原理细节、边界条件、项目落地、性能/安全/复杂度影响。

### Q2：重排和重绘区别？

重排是元素几何信息变化导致浏览器重新计算布局，重绘是外观变化导致重新绘制但不一定影响布局。重排成本通常更高，应避免频繁读写 layout 属性，动画优先使用 transform 和 opacity。

**关键词**：Layout、Paint、transform、opacity

**追问方向**：原理细节、边界条件、项目落地、性能/安全/复杂度影响。

### Q3：虚拟列表为什么有效？

虚拟列表只渲染可视区域及缓冲区内的节点，把大量 DOM 节点控制在稳定数量级，从而减少初始化、布局和更新成本。关键点是高度估算、滚动占位、缓冲区和动态高度处理。

**关键词**：虚拟列表、可视区、缓冲区、动态高度

**追问方向**：原理细节、边界条件、项目落地、性能/安全/复杂度影响。

### Q4：浏览器渲染流水线是什么？

浏览器从 HTML/CSS 解析开始，构建 DOM 和 CSSOM，再生成渲染树，经过 Layout 计算几何信息，Paint 绘制像素，最后 Composite 合成图层。优化时要尽量减少主线程上的 JS、样式计算和布局成本。

**关键词**：DOM、CSSOM、Layout、Paint、Composite

**追问方向**：原理细节、边界条件、项目落地、性能/安全/复杂度影响。

### Q5：如何减少强制同步布局？

强制同步布局通常来自先写 DOM 样式再立即读取 offsetWidth、getBoundingClientRect 等布局属性。优化方式是读写分离、批量更新、缓存布局结果，并使用 requestAnimationFrame 统一处理视觉更新。

**关键词**：强制同步布局、读写分离、rAF

**追问方向**：原理细节、边界条件、项目落地、性能/安全/复杂度影响。

### Q6：CSS 动画为什么推荐 transform/opacity？

transform 和 opacity 通常可以在合成线程处理，不必频繁触发布局和绘制，因此更适合高频动画。改变 width、height、top、left 等属性容易触发 layout，成本更高。

**关键词**：合成层、GPU、transform、opacity

**追问方向**：原理细节、边界条件、项目落地、性能/安全/复杂度影响。

### Q7：长列表除了虚拟列表还能怎么优化？

可以分页、懒加载、骨架屏、服务端筛选排序、减少单项组件复杂度、稳定 key、缓存测量结果，以及对不可见区域暂停图片和复杂交互。虚拟列表适合数量很大且滚动浏览的场景。

**关键词**：分页、懒加载、稳定 key、测量缓存

**追问方向**：原理细节、边界条件、项目落地、性能/安全/复杂度影响。

### Q8：如何优化图片渲染性能？

图片优化包括选择合适格式，使用 WebP/AVIF，按需裁剪尺寸，懒加载，响应式 srcset，设置 width/height 避免布局偏移，并对首屏关键图使用 preload。

**关键词**：WebP、AVIF、lazy、srcset、CLS

**追问方向**：原理细节、边界条件、项目落地、性能/安全/复杂度影响。

### Q9：requestAnimationFrame 有什么用？

requestAnimationFrame 会在浏览器下一次绘制前执行，适合做动画和视觉更新。相比 setTimeout，它更贴合刷新节奏，页面隐藏时也可能暂停，能减少不必要的计算。

**关键词**：rAF、动画、刷新率

**追问方向**：原理细节、边界条件、项目落地、性能/安全/复杂度影响。

### Q10：Web Worker 适合什么场景？

Web Worker 适合把大计算、解析、压缩、加密、数据转换等任务移出主线程，避免阻塞交互。但 Worker 与主线程通信有序列化成本，不适合频繁传递大量复杂对象的小任务。

**关键词**：Worker、主线程、序列化成本

**追问方向**：原理细节、边界条件、项目落地、性能/安全/复杂度影响。

### Q11：如何优化首屏渲染体验？

首屏体验可通过减少关键资源体积、内联关键 CSS、延迟非关键 JS、预加载关键资源、SSR/SSG、骨架屏和图片尺寸占位优化。重点是让用户更早看到稳定且可交互的内容。

**关键词**：首屏、关键 CSS、SSR、骨架屏

**追问方向**：原理细节、边界条件、项目落地、性能/安全/复杂度影响。

### Q12：如何衡量渲染性能优化效果？

可以结合实验室指标和真实用户指标。实验室用 Lighthouse、Performance；线上用 FCP、LCP、CLS、INP、长任务数量、JS 错误率和业务转化指标评估。

**关键词**：FCP、LCP、CLS、INP、RUM

**追问方向**：原理细节、边界条件、项目落地、性能/安全/复杂度影响。
