# 03-三、高级优化专题 - 标准答案索引

> 来源：[[03-三、高级优化专题]]。本页沉淀可直接用于面试表达的答案。

## 回答结构

- **结论**：先直接回答核心问题。
- **原理**：解释关键机制，不只背定义。
- **实践**：结合项目落地、指标或复杂度说明。
- **追问**：主动暴露可深入的方向。

## 高频标准答案

### Q1：前端性能优化如何系统回答？

先明确目标指标，例如 LCP、INP、CLS、首屏耗时和资源体积；再从加载链路、渲染链路、运行时交互、缓存策略和监控闭环拆解。最后结合项目讲优化前后的指标变化，避免只罗列手段。

**关键词**：指标体系、加载、渲染、缓存、监控

**追问方向**：原理细节、边界条件、项目落地、性能/安全/复杂度影响。

### Q2：首屏慢怎么排查？

先用 Performance、Lighthouse、WebPageTest 或 RUM 数据确认瓶颈在网络、资源、接口、渲染还是 hydration。常见优化包括压缩资源、拆包、预加载关键资源、SSR/SSG、图片优化、接口聚合和延迟非关键脚本。

**关键词**：首屏、LCP、TTFB、hydration、SSR

**追问方向**：原理细节、边界条件、项目落地、性能/安全/复杂度影响。

### Q3：长任务怎么治理？

长任务会阻塞主线程，导致输入响应变慢。治理方式包括拆分大计算、时间切片、requestIdleCallback、Web Worker、虚拟列表、减少同步布局，以及在 React 中用 transition 区分更新优先级。

**关键词**：Long Task、INP、Worker、时间切片

**追问方向**：原理细节、边界条件、项目落地、性能/安全/复杂度影响。

### Q4：如何建立前端性能指标体系？

指标体系应包含加载体验、交互体验、视觉稳定性、资源成本和业务结果。常用指标有 FCP、LCP、CLS、INP、TTFB、长任务、资源体积、缓存命中率和转化率。线上以 RUM 为准，实验室数据用于定位。

**关键词**：FCP、LCP、CLS、INP、RUM

**追问方向**：原理细节、边界条件、项目落地、性能/安全/复杂度影响。

### Q5：LCP 优化有哪些手段？

先找出 LCP 元素，通常是首屏大图、标题或主要内容块。优化方式包括降低 TTFB、预加载 LCP 资源、压缩图片、使用合适尺寸和格式、避免阻塞 CSS/JS、SSR 输出关键内容。

**关键词**：LCP、preload、图片、TTFB、关键资源

**追问方向**：原理细节、边界条件、项目落地、性能/安全/复杂度影响。

### Q6：INP 优化有哪些手段？

INP 关注用户交互到下一次绘制的延迟。优化方向是减少主线程长任务、降低事件处理函数复杂度、拆分渲染更新、避免同步布局、使用 transition/Worker，并优先治理高频核心交互。

**关键词**：INP、交互延迟、事件处理、主线程

**追问方向**：原理细节、边界条件、项目落地、性能/安全/复杂度影响。

### Q7：CLS 优化有哪些手段？

CLS 来自非预期布局偏移。优化方式包括为图片和广告预留尺寸、避免首屏动态插入内容、字体加载使用合适策略、动画使用 transform，骨架屏尺寸要与真实内容接近。

**关键词**：CLS、尺寸占位、字体、骨架屏

**追问方向**：原理细节、边界条件、项目落地、性能/安全/复杂度影响。

### Q8：性能监控 SDK 应该采集什么？

基础采集包括 Web Vitals、资源加载、接口耗时、JS 错误、白屏、长任务、页面路由和用户环境。还要支持采样、上报合并、异常去重、用户会话关联和隐私字段脱敏。

**关键词**：SDK、Web Vitals、错误、采样、脱敏

**追问方向**：原理细节、边界条件、项目落地、性能/安全/复杂度影响。

### Q9：如何做性能优化闭环？

闭环包括发现问题、定位瓶颈、制定方案、灰度上线、指标验证和持续监控。每次优化都要有基线、目标、实验范围和回滚策略，避免只做一次性手工优化。

**关键词**：基线、灰度、验证、回滚、持续监控

**追问方向**：原理细节、边界条件、项目落地、性能/安全/复杂度影响。

### Q10：资源加载优先级怎么优化？

首屏关键资源应尽早加载，例如 preload 关键 CSS、字体和 LCP 图片；非关键资源延迟或懒加载；prefetch 用于可能访问的后续路由。要避免过度 preload 抢占带宽。

**关键词**：preload、prefetch、懒加载、优先级

**追问方向**：原理细节、边界条件、项目落地、性能/安全/复杂度影响。

### Q11：Hydration 慢怎么优化？

Hydration 慢通常来自 JS 包过大、组件树复杂或首屏交互绑定成本高。可以通过减少客户端 JS、组件级懒加载、Streaming SSR、选择性 hydration、RSC 或 islands 架构降低成本。

**关键词**：hydration、Streaming SSR、RSC、islands

**追问方向**：原理细节、边界条件、项目落地、性能/安全/复杂度影响。

### Q12：性能优化如何避免负收益？

任何优化都要评估复杂度、维护成本、兼容性和真实收益。例如过度拆包可能增加请求和调度成本，过度缓存可能带来更新问题，过度 memo 可能增加比较成本。

**关键词**：负收益、复杂度、维护成本、取舍

**追问方向**：原理细节、边界条件、项目落地、性能/安全/复杂度影响。

## 复习建议

- 第二轮：对照关键词补齐遗漏点。
- 第三轮：为每个主题补充一个自己的项目案例。
