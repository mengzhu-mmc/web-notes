## 高频标准答案

### Q1：HTTP 缓存怎么答？

先区分强缓存与协商缓存。强缓存通过 Cache-Control/Expires 直接复用本地资源；协商缓存通过 ETag/Last-Modified 向服务端确认资源是否变化。项目中通常对带 hash 的静态资源设置长期强缓存，对 HTML 设置 no-cache 保证入口更新。

**关键词**：Cache-Control、ETag、Last-Modified、hash 静态资源、HTML no-cache

**追问方向**：原理细节、边界条件、项目落地、性能/安全/复杂度影响。

### Q2：HTTPS 为什么安全？

HTTPS 在 HTTP 与 TCP 之间加入 TLS。它通过证书验证身份，通过密钥协商生成会话密钥，再用对称加密传输数据，同时用摘要和签名保证完整性，主要解决窃听、篡改和冒充问题。

**关键词**：TLS、证书、密钥协商、对称加密、完整性

**追问方向**：原理细节、边界条件、项目落地、性能/安全/复杂度影响。

### Q3：从输入 URL 到页面展示发生了什么？

可以按 DNS 解析、TCP/TLS 建连、HTTP 请求响应、浏览器解析 HTML、构建 DOM/CSSOM、生成渲染树、布局绘制、执行 JS、加载子资源这条链路回答，再补充缓存、CDN、预加载等优化点。

**关键词**：DNS、TCP、TLS、DOM、CSSOM、渲染流水线

**追问方向**：原理细节、边界条件、项目落地、性能/安全/复杂度影响。

### Q4：HTTP/1.1、HTTP/2、HTTP/3 的核心区别？

HTTP/1.1 通过长连接和管线化改善连接复用，但仍有队头阻塞。HTTP/2 引入二进制分帧、多路复用、Header 压缩和 Server Push，解决应用层队头阻塞。HTTP/3 基于 QUIC/UDP，把可靠传输和拥塞控制放到用户态，进一步减少建连成本并缓解 TCP 层队头阻塞。

**关键词**：长连接、多路复用、队头阻塞、QUIC、UDP

**追问方向**：原理细节、边界条件、项目落地、性能/安全/复杂度影响。

### Q5：TCP 三次握手为什么不是两次？

三次握手的核心是让双方都确认自己的发送和接收能力，以及对方的发送和接收能力都正常。两次握手时服务端无法确认客户端是否收到自己的确认，也容易因为历史连接请求导致错误建立连接。

**关键词**：SYN、ACK、历史连接、双向确认

**追问方向**：原理细节、边界条件、项目落地、性能/安全/复杂度影响。

### Q6：TCP 四次挥手为什么需要 TIME_WAIT？

TIME_WAIT 主要有两个作用：保证最后一个 ACK 丢失时可以重传，确保对端能正常关闭；同时让旧连接中的延迟报文在网络中自然消失，避免影响相同四元组的新连接。

**关键词**：FIN、ACK、TIME_WAIT、延迟报文

**追问方向**：原理细节、边界条件、项目落地、性能/安全/复杂度影响。

### Q7：DNS 解析过程怎么答？

浏览器会先查本地缓存、系统缓存、hosts 和本地 DNS；如果没有命中，本地 DNS 会从根域名服务器、顶级域名服务器、权威域名服务器逐级查询，最终得到 IP。工程上可通过 DNS Prefetch、CDN 和合理 TTL 优化解析耗时。

**关键词**：DNS 缓存、递归查询、迭代查询、TTL、DNS Prefetch

**追问方向**：原理细节、边界条件、项目落地、性能/安全/复杂度影响。

### Q8：CORS 跨域怎么答？

CORS 是浏览器同源策略下的跨域资源访问机制。简单请求会直接发送并校验响应头；复杂请求会先发 OPTIONS 预检。服务端需要配置 Access-Control-Allow-Origin、Methods、Headers，带 Cookie 时还要配置 Credentials 且 Origin 不能是通配符。

**关键词**：同源策略、预检请求、OPTIONS、Credentials

**追问方向**：原理细节、边界条件、项目落地、性能/安全/复杂度影响。

### Q9：Cookie、localStorage、sessionStorage 区别？

Cookie 会随请求自动携带，适合会话标识但要注意体积和安全；localStorage 持久存在，适合非敏感本地配置；sessionStorage 只在当前标签页会话内有效。敏感信息不应直接放在 Web Storage 中。

**关键词**：Cookie、localStorage、sessionStorage、SameSite、HttpOnly

**追问方向**：原理细节、边界条件、项目落地、性能/安全/复杂度影响。

### Q10：XSS 和 CSRF 怎么防？

XSS 是注入恶意脚本，防护重点是输入校验、输出转义、CSP、避免直接 innerHTML、Cookie 设置 HttpOnly。CSRF 是借用户登录态发起伪造请求，防护重点是 SameSite、CSRF Token、Referer/Origin 校验和关键操作二次确认。

**关键词**：XSS、CSRF、CSP、SameSite、Token

**追问方向**：原理细节、边界条件、项目落地、性能/安全/复杂度影响。

### Q11：CDN 为什么能加速？

CDN 把静态资源缓存到离用户更近的边缘节点，减少网络传输距离和源站压力。它通常结合 DNS 调度、缓存策略、回源控制、压缩和 HTTP/2/3 使用。要关注缓存命中率、刷新预热和版本化发布。

**关键词**：CDN、边缘节点、缓存命中率、回源、预热

**追问方向**：原理细节、边界条件、项目落地、性能/安全/复杂度影响。

### Q12：前端如何做网络性能优化？

可以从减少请求数、减少资源体积、提升缓存命中率、缩短关键链路、优化协议和提升并发利用率入手。典型手段包括资源压缩、代码分割、HTTP 缓存、CDN、preload/prefetch、图片优化、接口聚合和降级重试。

**关键词**：请求数、资源体积、缓存、preload、接口聚合

**追问方向**：原理细节、边界条件、项目落地、性能/安全/复杂度影响。
