## 五、微前端

### Q: 什么是微前端？主流方案有哪些？

**难度**：⭐⭐⭐⭐ | **频率**：🔥🔥🔥

**答：**

微前端是将大型前端应用拆分成多个**独立开发、独立部署、独立运行**的小应用（子应用），在主应用（基座）中按需加载和组合的架构方案。

**核心解决的问题：**

```
问题：大型前端项目
  - 多团队协作，代码耦合严重
  - 技术栈升级困难（React 16 → 18，Angular → React）
  - 构建时间长，部署互相阻塞
  - 复用困难（A 团队的组件，B 团队要复制一份）

微前端解决：
  - 每个子应用独立 git 仓库、独立 CI/CD
  - 子应用可用不同技术栈（主应用 React，子应用 Vue）
  - 子应用独立发布，互不影响
```

**主流方案对比：**

**① qiankun（阿里，基于 single-spa）**

```js
// 主应用（基座）
import { registerMicroApps, start } from 'qiankun';

registerMicroApps([
  {
    name: 'react-app',
    entry: '//localhost:7100',  // 子应用的 HTML 入口
    container: '#subapp',       // 挂载到主应用的哪个 DOM 节点
    activeRule: '/react',       // 路由匹配规则
    props: {                    // 主→子通信
      token: getToken(),
      onUserChange: (user) => { ... },
    },
  },
  {
    name: 'vue-app',
    entry: '//localhost:7200',
    container: '#subapp',
    activeRule: '/vue',
  },
]);

start({
  prefetch: 'all',     // 预加载所有子应用（空闲时）
  sandbox: {
    strictStyleIsolation: true,  // Shadow DOM 样式隔离
    // 或 experimentalStyleIsolation: true（CSS Scope 方式，scoped）
  },
});

// ------------------------------------------------
// 子应用（React 子应用适配）
// src/index.ts
import { createRoot } from 'react-dom/client';
import App from './App';

let root: ReturnType<typeof createRoot>;

// qiankun 生命周期钩子（必须 export）
export async function bootstrap() {
  console.log('[react-app] bootstrap');
}

export async function mount(props: any) {
  const { container, onGlobalStateChange } = props;
  // container 是 qiankun 传入的 DOM 节点，避免直接用 document.getElementById
  const mountNode = container
    ? container.querySelector('#root')
    : document.getElementById('root');

  root = createRoot(mountNode);
  root.render(<App />);

  // 监听全局状态变化（主→子通信）
  onGlobalStateChange?.((state: any) => {
    store.dispatch(updateGlobalState(state));
  });
}

export async function unmount() {
  root.unmount();  // 销毁子应用
}

// 独立运行时的入口（子应用也可以独立跑）
if (!window.__POWERED_BY_QIANKUN__) {
  root = createRoot(document.getElementById('root')!);
  root.render(<App />);
}
```

**② Module Federation（webpack5，字节/众多大厂使用）**

```js
// webpack.config.js（远程应用 remote-app）
const { ModuleFederationPlugin } = require("webpack").container;

module.exports = {
  plugins: [
    new ModuleFederationPlugin({
      name: "remoteApp", // 本应用的名称
      filename: "remoteEntry.js", // 入口文件名
      exposes: {
        // 暴露给其他应用使用的模块
        "./Button": "./src/components/Button",
        "./utils": "./src/utils/index",
      },
      shared: {
        // 共享依赖（避免重复加载）
        react: { singleton: true, requiredVersion: "^18.0.0" },
        "react-dom": { singleton: true, requiredVersion: "^18.0.0" },
      },
    }),
  ],
};

// webpack.config.js（主应用 host-app）
module.exports = {
  plugins: [
    new ModuleFederationPlugin({
      name: "hostApp",
      remotes: {
        // 引用远程应用（name@remoteEntry.js地址）
        remoteApp: "remoteApp@http://localhost:3001/remoteEntry.js",
      },
      shared: {
        react: { singleton: true },
        "react-dom": { singleton: true },
      },
    }),
  ],
};

// 主应用中使用远程组件（动态 import）
const RemoteButton = React.lazy(() => import("remoteApp/Button"));

function App() {
  return (
    <Suspense fallback="Loading...">
      <RemoteButton onClick={() => alert("clicked!")} />
    </Suspense>
  );
}
```

**方案对比：**

| 方案 | 隔离 | 通信 | 技术栈无关 | 独立部署 | 适用场景 |
| --- | --- | --- | --- | --- | --- |
| **qiankun** | JS 沙箱 + CSS 隔离 | Props + 全局状态 | ✅ | ✅ | 大型后台系统，多团队 |
| **Module Federation** | 无（共享运行时） | Import 直接引用 | ⚠️（需要共享 runtime） | ✅ | 组件/功能共享，同技术栈 |
| **iframe** | 完全隔离 | postMessage | ✅ | ✅ | 强隔离需求，安全敏感 |
| **Web Components** | Shadow DOM | Events | ✅ | ✅ | 跨框架组件库 |

**🔍 深层原理**

**qiankun 的 JS 沙箱机制：**

```js
// qiankun 的 Proxy 沙箱（ProxySandbox）
class ProxySandbox {
  private fakeWindow = {};
  private proxy: WindowProxy;

  constructor() {
    const rawWindow = window;
    const fakeWindow = this.fakeWindow;

    // 用 Proxy 拦截对 window 的读写
    this.proxy = new Proxy(fakeWindow, {
      set(target, key, value) {
        // 所有对 window 的写操作都写到 fakeWindow
        target[key] = value;
        return true;
      },
      get(target, key) {
        // 读取时：先找 fakeWindow，找不到再找真实 window
        return key in target ? target[key] : rawWindow[key];
      },
    });
  }

  active()   { /* 激活沙箱，子应用的 window 指向 proxy */ }
  inactive() { /* 冻结沙箱，清理子应用对全局的污染 */ }
}
// 这样子应用的 window.xxx = yyy 不会污染主应用的真实 window
```

**🎯 面试追问**

- **Q: qiankun 和 single-spa 的关系是什么？**
  - A: `single-spa` 是底层框架，提供了子应用注册、生命周期管理（bootstrap/mount/unmount）的基础能力；`qiankun` 是基于 single-spa 的上层封装，额外提供了：HTML Entry（通过 fetch 加载子应用 HTML）、JS 沙箱（Proxy 隔离 window）、CSS 隔离、子应用通信（全局状态）、预加载等开箱即用的能力。
- **Q: 微前端如何处理主子应用间的路由冲突？**
  - A: qiankun 通过 `activeRule` 规则匹配路由，主应用监听 `popstate`/`hashchange` 事件决定加载哪个子应用。子应用内部的路由需要配置 `base`（hash 路由加前缀，history 路由设 basename）。常见方案：主应用用 history 模式，子应用也用 history 模式并配置 basename 为子应用前缀。
- **Q: Module Federation 在运行时是如何加载远程模块的？**
  - A: 运行时动态加载 `remoteEntry.js`（JSONP），这个文件暴露了远程应用的模块容器（container），包含 `get(moduleName)` 方法。`import('remoteApp/Button')` 实际上是：1. 加载 `remoteEntry.js` → 2. 调用 `remoteApp.get('./Button')` → 3. 返回模块的 factory 函数 → 4. 执行得到模块导出。

**⚠️ 常见误区**

- ❌ 微前端 = iframe → iframe 是最简单的实现，但有性能和交互限制；qiankun/MF 有更好的集成体验
- ❌ qiankun 的沙箱能完全隔离所有副作用 → 沙箱主要隔离 window，DOM 操作、定时器等仍可能泄露，需要在 unmount 里手动清理
- ❌ Module Federation 只是微前端方案 → MF 本质是模块共享方案（runtime 代码共享），也可用于非微前端场景（如跨应用共享组件库）
