# 04-四、模块化

## 四、模块化

### Q: 前端模块化的发展历史是什么？

**难度**：⭐⭐⭐ | **频率**：🔥🔥🔥

**答：**

```
全局变量阶段 → IIFE → CommonJS → AMD/CMD → UMD → ESM（现代标准）
```

**各阶段演进：**

**① 全局变量（2005 年前）**

```js
// 所有代码在全局作用域，污染严重，依赖顺序靠 <script> 标签顺序保证
var utils = {
  add: function (a, b) {
    return a + b;
  },
};
var app = {
  init: function () {
    console.log(utils.add(1, 2));
  },
};
// 命名冲突、依赖管理全靠人工，项目大了噩梦
```

**② IIFE（立即调用函数，2010 年前）**

```js
// 用闭包模拟私有作用域，通过参数注入依赖
var MyModule = (function ($, utils) {
  var privateVar = "secret"; // 私有变量

  return {
    publicMethod: function () {
      return utils.add(1, 2);
    },
  };
})(jQuery, utils); // 显式传入依赖

// 依然需要手动保证 <script> 加载顺序
```

**③ CommonJS（Node.js，2009 年）**

```js
// Node.js 采用，同步加载（适合服务器端，文件读取速度快）
// 规范：每个文件是一个模块，有自己的作用域

// math.js
const PI = 3.14159;
function add(a, b) {
  return a + b;
}
module.exports = { PI, add }; // 导出

// app.js
const { PI, add } = require("./math"); // 导入（同步，运行时执行）
const axios = require("axios"); // 加载 node_modules

// CJS 特点：
// 1. 运行时加载（require 是函数调用）
// 2. 导出的是值的拷贝（修改导出对象不影响其他模块）
// 3. 支持动态路径：require('./' + moduleName)
// 4. 循环依赖时返回已执行部分的导出（可能是不完整的对象）
```

**④ AMD（Asynchronous Module Definition，2010 年）**

```js
// RequireJS 实现，专为浏览器设计，异步加载
// 解决了 CJS 同步加载在浏览器中会阻塞页面的问题

// 定义模块
define("math", ["dependency1"], function (dep1) {
  return {
    add: function (a, b) {
      return a + b;
    },
  };
});

// 使用模块（异步回调）
require(["math", "jquery"], function (math, $) {
  console.log(math.add(1, 2));
});

// CMD（Sea.js）是国内的类似方案，延迟执行依赖
// 区别：AMD 依赖前置（定义时声明），CMD 依赖就近（使用时声明）
```

**⑤ UMD（Universal Module Definition，2011 年）**

```js
// 兼容 CJS、AMD、全局变量的通用格式
// 通常是库作者用来发布可在多环境使用的包
(function (root, factory) {
  if (typeof define === "function" && define.amd) {
    define(["dependency"], factory); // AMD 环境
  } else if (typeof module === "object" && module.exports) {
    module.exports = factory(require("dependency")); // CJS 环境
  } else {
    root.MyLibrary = factory(root.Dependency); // 浏览器全局
  }
})(typeof self !== "undefined" ? self : this, function (Dependency) {
  // 模块代码
  return {
    /* 导出 */
  };
});
```

**⑥ ESM（ECMAScript Modules，ES2015/2015+）**

```js
// 语言标准级别的模块系统，静态分析友好
// math.js
export const PI = 3.14159;
export function add(a, b) { return a + b; }
export default class Calculator { ... }

// app.js
import { PI, add } from './math.js';    // 命名导入（静态）
import Calculator from './math.js';     // 默认导入
import * as math from './math.js';      // 命名空间导入
import('./heavy.js').then(m => m.default); // 动态导入（返回 Promise）

// ESM 特点（与 CJS 的核心区别）：
// 1. 静态结构：import/export 只能在模块顶层（编译时确定依赖）
// 2. 导出的是绑定（binding），而非值拷贝（模块内修改对外可见！）
// 3. 异步加载（浏览器原生支持）
// 4. 循环依赖处理更完善（导出绑定，不是快照）
// 5. 支持 Tree Shaking（正是因为静态分析）
```

**CJS vs ESM 的核心区别（高频考点）：**

```js
// ===== 导出值 vs 导出绑定 =====

// CJS：导出的是值的拷贝
// counter.js (CJS)
let count = 0;
module.exports = { count, increment: () => count++ };

// main.js
const counter = require("./counter");
counter.increment();
console.log(counter.count); // 0 ！！（拷贝的旧值，不是最新值）

// ESM：导出的是实时绑定
// counter.js (ESM)
export let count = 0;
export const increment = () => count++;

// main.js
import { count, increment } from "./counter";
increment();
console.log(count); // 1 ✅（实时绑定，反映最新值）
```

**🔍 深层原理**

浏览器从 Chrome 61（2017）、Safari 10.1、Firefox 60 开始支持原生 ESM（`<script type="module">`）。Node.js 从 v12 开始实验性支持，v14 LTS 稳定支持（`.mjs` 扩展名或 `package.json` 中 `"type": "module"`）。

**💡 踩坑点**

```js
// 坑1：ESM 和 CJS 不能随意混用
// ❌ 在 ESM 文件里用 require（报错：require is not defined）
// ❌ 在 CJS 文件里用顶层 await（CJS 不支持顶层 await）

// 坑2：Node.js 中 .js 文件的模块类型取决于 package.json 的 type 字段
// "type": "module" → .js 文件默认是 ESM
// "type": "commonjs"（或无此字段）→ .js 文件默认是 CJS
// 强制指定：.mjs 强制 ESM，.cjs 强制 CJS

// 坑3：ESM 循环依赖不报错，但可能拿到 undefined
// a.js: import { b } from './b.js';   console.log(b); // 可能 undefined
// b.js: import { a } from './a.js';   export const b = 1;
// 循环依赖时，先执行的模块拿到的是"还没初始化完"的绑定
```

**🎯 面试追问**

- **Q: 为什么 CJS 不能被 Tree Shaking？**
  - A: CJS 的 `require` 是运行时函数调用，可以动态拼路径（`require('./' + name)`），编译时无法确定导入了哪些符号。webpack 必须保守地包含整个模块。ESM 的 `import` 是关键字，编译时静态确定，可以精确分析哪些导出被用到。
- **Q: Node.js 中如何在 ESM 模块里使用 `__dirname`？**
  - A: ESM 模块里没有 CJS 的 `__dirname`/`__filename` 全局变量，需要用 `import.meta.url`：`const __dirname = path.dirname(new URL(import.meta.url).pathname);`
- **Q: AMD 为什么被 ESM 取代了？**
  - A: AMD 需要加载器（RequireJS），语法相对繁琐，且不是语言标准；ESM 是 ES2015 语言规范，浏览器和 Node.js 原生支持，无需额外工具，语法更简洁，且支持静态分析（Tree Shaking）。HTTP/2 的多路复用也让 AMD 的合并请求优势不再显著。

**⚠️ 常见误区**

- ❌ CommonJS 是 Node.js 专用的，浏览器不支持 → 通过 webpack/Rollup 打包后浏览器也能运行 CJS（构建工具模拟了模块系统）
- ❌ `import { x } from './mod'` 和 CJS `const { x } = require('./mod')` 完全等价 → ESM 导出的是绑定（实时），CJS 是值拷贝
- ❌ ESM 的 `import()` 动态导入和 `import` 语句一样是静态的 → `import()` 是函数调用，是动态的，运行时执行，返回 Promise
