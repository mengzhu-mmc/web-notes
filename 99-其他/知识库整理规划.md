## 后续治理规则

1. **先合并再删除**：重复笔记先抽取到主干文档，确认内容已覆盖后再删除旧文档。
2. **先修入口再修细节**：优先保证根索引、模块索引、重点专题入口可用。
3. **一文一个主标题**：长文内部层级使用二级及以下标题，多 H1 文档逐步改造。
4. **课程笔记单独归档**：课程型资料统一沉到各模块 `课程笔记/` 目录，不与主干知识文档混排。
5. **新增链接用相对路径**：仓库正在从 Obsidian 双链迁移到相对路径 Markdown 链接，后者在 GitHub 与 Obsidian 中都能跳转。文件名含空格时用 `%20` 编码，或直接避免空格。
6. **删除前先核实内容，且不要只统计 `.md`**：目录名不可信，文件类型也不能只看一种。两个真实教训——
   - `档案_13面试题_重复备份` 名为「重复备份」，实际藏着网络题库、场景设计题库、复习闪卡的**唯一副本**；
   - `00-原始旧笔记备份` 的 16 个 md 确实是空壳跳转桩，但同目录下还有 **123 个可运行的 HTML demo 与 CSS/LESS/SCSS 文件**，只用 `find -name '*.md'` 统计会得出「整个目录都是空壳」的错误结论。
   
   正确做法：删除前用 `find <dir> -type f | wc -l` 看**全部文件数**，再按扩展名分类确认，最后用 `grep` 验证正文是否在别处存在。
