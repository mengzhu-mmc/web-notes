## 高频标准答案

### Q1：type 和 interface 怎么选？

interface 更适合描述对象结构和可扩展声明合并，type 更适合联合类型、交叉类型、条件类型等组合表达。团队中通常对象模型优先 interface，复杂类型运算优先 type，关键是保持一致性。

**关键词**：interface、type、声明合并、联合类型

**追问方向**：原理细节、边界条件、项目落地、性能/安全/复杂度影响。

### Q2：unknown 和 any 区别？

any 会绕过类型检查，使用后基本失去类型安全；unknown 表示未知类型，使用前必须做类型收窄。因此对外部输入、JSON 解析、错误对象等不确定数据，优先用 unknown 再校验。

**关键词**：unknown、any、类型收窄、类型安全

**追问方向**：原理细节、边界条件、项目落地、性能/安全/复杂度影响。

### Q3：泛型解决什么问题？

泛型把类型作为参数传入，使函数、类或组件在保持类型安全的同时支持多种数据结构。它常用于请求封装、组件 props、工具函数和类型工具。

**关键词**：泛型、类型参数、复用、约束

**追问方向**：原理细节、边界条件、项目落地、性能/安全/复杂度影响。

### Q4：联合类型和交叉类型区别？

联合类型表示值可以是多个类型之一，使用时只能访问公共成员，需要类型收窄。交叉类型表示同时满足多个类型，常用于组合对象能力。可以简单理解为 union 是“或”，intersection 是“且”。

**关键词**：union、intersection、类型收窄

**追问方向**：原理细节、边界条件、项目落地、性能/安全/复杂度影响。

### Q5：类型收窄有哪些方式？

常见方式包括 typeof、instanceof、in、字面量判等、判别联合、自定义类型守卫和控制流分析。类型收窄的目标是在安全分支内获得更具体的类型。

**关键词**：typeof、in、instanceof、判别联合、类型守卫

**追问方向**：原理细节、边界条件、项目落地、性能/安全/复杂度影响。

### Q6：never 类型有什么用？

never 表示永远不会出现的值，常用于抛错函数、无限循环和穷尽检查。在判别联合的 switch 中，可以用 never 确保所有分支都被处理，遗漏类型时编译器会报错。

**关键词**：never、穷尽检查、判别联合

**追问方向**：原理细节、边界条件、项目落地、性能/安全/复杂度影响。

### Q7：条件类型怎么理解？

条件类型形如 T extends U ? X : Y，根据类型关系选择不同结果。它常用于工具类型和类型推导。配合泛型和 infer，可以从函数、数组、Promise 等结构中提取内部类型。

**关键词**：conditional type、extends、infer

**追问方向**：原理细节、边界条件、项目落地、性能/安全/复杂度影响。

### Q8：infer 有什么用？

infer 用于在条件类型中声明待推断的类型变量。例如从 Promise<T> 中提取 T，从函数类型中提取参数或返回值。它让复杂类型转换更可读。

**关键词**：infer、ReturnType、Parameters、Awaited

**追问方向**：原理细节、边界条件、项目落地、性能/安全/复杂度影响。

### Q9：keyof 和 typeof 在类型中怎么用？

keyof 获取对象类型的键联合，typeof 在类型上下文中获取变量的静态类型。二者常配合 as const 使用，把运行时对象转换为可复用的类型约束。

**关键词**：keyof、typeof、as const、键联合

**追问方向**：原理细节、边界条件、项目落地、性能/安全/复杂度影响。

### Q10：Partial、Pick、Omit 怎么实现？

这些工具类型基于映射类型和 keyof。Partial 把属性变可选，Pick 选取指定键，Omit 通常基于 Pick 和 Exclude 排除指定键。理解它们有助于手写业务类型工具。

**关键词**：Partial、Pick、Omit、mapped type

**追问方向**：原理细节、边界条件、项目落地、性能/安全/复杂度影响。

### Q11：React 中如何给组件 props 建模？

简单组件可直接定义 Props interface；带 children 用 PropsWithChildren 或显式 children；事件处理使用 React.MouseEvent 等类型；泛型组件要注意推断和默认类型参数。

**关键词**：React Props、children、事件类型、泛型组件

**追问方向**：原理细节、边界条件、项目落地、性能/安全/复杂度影响。

### Q12：如何给接口请求做类型封装？

可以定义统一的 Response<T>、PageResult<T> 和 request<T>，让调用方传入响应数据类型。外部数据仍需运行时校验，TypeScript 只能保证编译期类型，不保证服务端真实返回。

**关键词**：request<T>、Response<T>、运行时校验

**追问方向**：原理细节、边界条件、项目落地、性能/安全/复杂度影响。
