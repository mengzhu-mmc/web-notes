# AI 学习计划：前端工程师 4 周路线

> 目标：从“会用 AI 工具”升级到“能设计、实现、评审 AI 前端应用”。计划默认每天 45-60 分钟，周末做项目整合。

## 第 1 周：AI 应用基础与调用链路

### 学习目标

- 理解 LLM、上下文窗口、token、temperature、结构化输出、流式输出。
- 能用后端代理完成一次安全的模型调用。
- 能解释为什么生产环境不能从浏览器直接调用模型 API。

### 每日安排

1. **Day 1：基础概念**
   - 复习 `91-AI前端/AI前端工程师指南.md` 的 LLM、Prompt、模型边界章节。
   - 输出一页笔记：模型擅长什么、不擅长什么。
2. **Day 2：后端代理与密钥安全**
   - 做一个最小 Node / Next.js API Route，把前端请求转发到模型服务。
   - 重点记录：鉴权、限流、日志脱敏、错误兜底。
3. **Day 3：流式输出**
   - 实现一个流式聊天 UI，区分 loading、streaming、done、error。
4. **Day 4：结构化输出**
   - 用 schema 约束模型输出，练习 JSON 解析失败后的重试策略。
5. **Day 5：成本与性能**
   - 记录上下文裁剪、历史压缩、小模型优先、缓存等策略。
6. **周末项目**
   - 做一个“AI 面试题解释器”：输入题目 → 输出知识点、常见追问、示例代码、风险提示。

## 第 2 周：RAG 与知识库问答

### 学习目标

- 理解 embedding、切片、召回、重排、引用来源。
- 能把本地 Markdown 知识库做成一个最小问答原型。
- 能识别 RAG 的幻觉、过期资料、文档投毒风险。

### 每日安排

1. **Day 1：RAG 心智模型**
   - 画出 query → rewrite → retrieve → rerank → generate → cite 的流程图。
2. **Day 2：Markdown 切片**
   - 以标题层级和段落为边界切片，保留文件路径、标题、更新时间。
3. **Day 3：检索与引用**
   - 答案中必须附来源路径；没有召回依据时返回“不确定”。
4. **Day 4：前端交互**
   - 做引用卡片、展开原文、复制答案、反馈按钮。
5. **Day 5：安全检查**
   - 增加 prompt injection 提示、敏感信息过滤、来源白名单。
6. **周末项目**
   - 做一个“web-notes AI 检索助手”的本地原型，只读仓库内容，不写入文件。

## 第 3 周：MCP、工具调用与 Agent 工作流

### 学习目标

- 理解 MCP Host / Client / Server / Tool 分工。
- 能设计一个只读工具和一个需要审批的写工具。
- 能解释 LLM “调用工具”与程序真正执行工具之间的差异。

### 每日安排

1. **Day 1：MCP 原理复习**
   - 阅读 `09-工程化/MCP协议原理与协作流程.md`。
   - 画出 Host、Client、Server、Tool 的 18 步协作流程。
2. **Day 2：只读工具设计**
   - 设计 `search_notes`：输入关键词，返回文件、标题、片段。
3. **Day 3：写操作审批**
   - 设计 `create_note_draft`：只生成草稿，不直接提交。
4. **Day 4：Agent loop 控制**
   - 设定最大步骤数、最大工具调用次数、超时和失败策略。
5. **Day 5：审计与回放**
   - 记录每次工具调用的输入摘要、输出摘要、操作者、时间。
6. **周末项目**
   - 做一个“AI 笔记整理 Agent”设计文档：只读扫描 → 生成计划 → 人工确认 → 写入草稿 → Prettier → diff 审阅。

## 第 4 周：AI 前端产品化与面试表达

### 学习目标

- 能把 AI 功能做成稳定、可解释、可恢复的前端体验。
- 能在面试中讲清 AI 项目的架构、安全和工程质量。
- 形成 2-3 个可展示项目案例。

### 每日安排

1. **Day 1：状态设计**
   - 把 AI 任务拆成 idle、submitting、streaming、tool-running、needs-approval、done、error、cancelled。
2. **Day 2：可解释 UI**
   - 展示模型正在做什么，但不暴露原始 chain-of-thought。
3. **Day 3：人工确认**
   - 对删除、提交、发送、支付等动作加确认与回滚。
4. **Day 4：质量评测**
   - 设计 golden cases：正确性、引用质量、拒答、注入攻击、超时。
5. **Day 5：面试复盘**
   - 准备 3 个 STAR 案例：AI 知识库、AI 表单助手、AI 代码审查。
6. **周末项目**
   - 选择一个项目写成作品集文档：背景、架构、关键代码、安全设计、效果和复盘。

## 最终验收清单

- 能说清 MCP / A2A / AG-UI 的分层区别。
- 能独立实现一个流式 AI UI。
- 能实现一个带来源引用的 RAG 问答。
- 能设计工具调用审批和审计日志。
- 能解释 AI 生成代码的风险，并进行人工 Review。
- 能把 AI 项目讲成工程项目，而不是“调了一个模型接口”。
