## 一、本周主线判断

本周 AI 学习重点不再只是“会调用一个聊天接口”，而是要把 AI 应用拆成四层：**模型能力层、工具/数据连接层、Agent 协作层、前端交互层**。

- **模型能力层**：理解提示词、上下文窗口、结构化输出、工具调用、流式输出、成本与延迟。
- **工具/数据连接层**：用 MCP 把模型和外部系统连接起来，避免每个应用重复设计私有工具协议。MCP 是连接 AI 应用与外部系统的开源标准，可连接数据源、工具和工作流[[What is the Model Context Protocol (MCP)?]](https://modelcontextprotocol.io/docs/getting-started/intro)。
- **Agent 协作层**：用 A2A 解决不同 Agent 之间的能力发现、任务管理、消息协作和产物交付。Google 发布的 A2A 是开放协议，目标是让不同供应商或框架构建的 Agent 能安全交换信息并协调行动[[Announcing the Agent2Agent Protocol (A2A)]](https://developers.googleblog.com/en/a2a-a-new-era-of-agent-interoperability/)。
- **前端交互层**：用 AG-UI、AI SDK UI 等方案，把长任务、流式事件、工具执行状态、人工确认和生成式 UI 做成可解释、可中断、可恢复的用户体验。AG-UI 是一个开放、轻量、事件驱动协议，用于标准化 AI Agent 与用户侧应用之间的连接[[AG-UI Overview]](https://docs.ag-ui.com/introduction)。

## 二、AI Agent 协议心智模型

### 1. MCP：Agent ↔ 工具 / 数据

MCP 的关键不是“又一个插件系统”，而是把工具能力标准化：Host 负责用户交互与权限控制，Client 负责协议通信，Server 暴露工具、资源或工作流。

学习时应重点掌握：

1. **能力发现**：Host 先拿到 Server 暴露的工具清单和参数 Schema。
2. **调用决策**：LLM 只生成调用意图，真正执行由 Host / Client / Server 完成。
3. **安全边界**：工具参数来自模型输出和用户输入，执行前必须校验、鉴权、限流、记录审计日志。
4. **本地与远程差异**：本地 stdio 适合个人工具；远程 HTTP 适合团队共享，但权限和网络暴露面更大。

> 与仓库内 `09-工程化/MCP协议原理与协作流程.md` 的关系：该文件继续作为 MCP 原理主文档；本文只保留学习路线与 AI 前端视角。

### 2. A2A：Agent ↔ Agent

A2A 适合多 Agent 协作：一个 Agent 负责拆任务，另一个 Agent 负责检索，另一个 Agent 负责执行，最后由协调者汇总产物。A2A 的设计原则包括基于 HTTP、SSE、JSON-RPC 等既有标准，支持企业级认证授权、长任务和多模态场景[[Announcing the Agent2Agent Protocol (A2A)]](https://developers.googleblog.com/en/a2a-a-new-era-of-agent-interoperability/)。

前端工程师需要关注的是：

- UI 如何展示“任务正在由哪个 Agent 处理”。
- 长任务如何展示进度、阶段、可取消入口和最终 artifact。
- 用户如何在关键节点做确认、改写或驳回。
- 多 Agent 失败时如何定位责任：输入问题、工具问题、权限问题、模型问题，还是协调器问题。

### 3. AG-UI：Agent ↔ 用户界面

AG-UI 的定位更贴近前端：它关心 Agent 状态、UI 意图和用户交互如何在 Agent 后端与前端应用之间流动。AG-UI 文档把 MCP、A2A、AG-UI 分成三层：MCP 面向工具和数据，A2A 面向 Agent 间协作，AG-UI 面向 Agent 与用户应用交互[[AG-UI Overview]](https://docs.ag-ui.com/introduction)。

可落地的前端能力包括：

- 流式聊天与事件流。
- 工具调用状态渲染。
- 人工审批与中断恢复。
- 共享状态与事件溯源。
- 生成式 UI 的受控渲染。

## 三、AI 前端技术栈收敛

### 1. AI SDK / React / Next.js

AI SDK 是面向 TypeScript 的 AI 应用与 Agent 工具包，覆盖 React、Next.js、Vue、Svelte、Node.js 等应用场景[[AI SDK by Vercel]](https://ai-sdk.dev/docs/introduction)。对于 React / Next.js 学习路线，优先掌握以下能力：

1. **流式 UI**：把模型输出、工具状态、结构化数据流转成可渐进渲染的 UI。
2. **消息持久化**：区分 UI 消息和模型消息，避免把前端展示状态直接当作模型上下文。
3. **工具调用可视化**：把工具入参、执行中、成功、失败、重试做成可解释状态。
4. **Agent loop 控制**：限制步骤数、审批危险工具、设置中断点，避免失控循环。
5. **RAG 与知识库**：把检索、引用、答案生成拆开，答案必须保留来源和置信边界。

AI SDK 5 强调 type-safe chat、Agentic Loop Control、工具改进和前后端类型安全[[AI SDK 5]](https://vercel.com/blog/ai-sdk-5)。学习时不要只复制 Demo，而要把“类型安全 + 流式状态 + 工具权限 + 持久化”作为一个整体来练。

### 2. React + AI 的典型项目

建议本仓库后续围绕三个小项目持续迭代：

- **AI 知识库问答**：Markdown → 切片 → embedding → 检索 → 带引用回答。
- **AI 表单助手**：用户输入 → schema 校验 → 模型建议 → 用户确认后写入。
- **AI 代码审查助手**：diff → 风险分类 → 修复建议 → 人工确认 → 生成 patch。

这些项目能覆盖前端、工程化、AI 调用、安全边界和面试表达，是比单纯背 API 更高价值的学习路径。

## 六、安全与质量边界

AI 前端工程不是“让模型能做事”这么简单，真正难点是让它**可控地做事**。

必须长期保留的安全原则：

1. **密钥不进前端**：生产环境必须经过后端代理，前端不得暴露真实模型 Key。
2. **工具调用要审批**：文件写入、网络请求、数据库变更、支付、删除等操作必须有人类确认或策略审批。
3. **检索结果要防投毒**：RAG 文档、网页、用户上传内容都可能包含 prompt injection。
4. **输出要可追溯**：涉及事实、资料、版本、价格、政策时必须引用来源。
5. **长任务要可取消**：Agent 任务要有取消、超时、重试和状态恢复机制。
