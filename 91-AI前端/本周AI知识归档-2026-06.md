## 二、Vercel AI SDK 6：流式与工具调用的事实标准

Vercel AI SDK 已成为在 Next.js 与更广 React 生态中集成大模型的事实标准，核心是统一、流式优先、可在 Edge 运行的 API，覆盖所有主流模型供应商[[The Ultimate Guide to Vercel AI SDK 2026]](https://nextfuture.io.vn/blog/ultimate-guide-vercel-ai-sdk-2026)。

### 本周要点（v6 关键面）

- **`useChat` 的 message-parts 模型**：一条消息由多个「part」组成（文本、工具调用、推理、附件等），客户端据此渲染并天然支持乐观 UI（optimistic UI）[[Vercel AI SDK 6 Deep Dive]](https://www.digitalapplied.com/blog/vercel-ai-sdk-6-deep-dive-features-tool-calls-2026)。
- **`streamText` 作为服务端原语**：负责把推理强度（reasoning effort）路由到合适的处理路径，是服务端流式的正确入口[[Vercel AI SDK 6 Deep Dive]](https://www.digitalapplied.com/blog/vercel-ai-sdk-6-deep-dive-features-tool-calls-2026)。
- **工具调用 + Zod**：用 Zod 描述工具入参 schema，覆盖完整的「调用—执行—回填」生命周期[[Vercel AI SDK 6 Deep Dive]](https://www.digitalapplied.com/blog/vercel-ai-sdk-6-deep-dive-features-tool-calls-2026)。
- **provider 适配层**：同一套代码切换 Anthropic、OpenAI、Google、Mistral、xAI 等供应商[[Vercel AI SDK 6 Deep Dive]](https://www.digitalapplied.com/blog/vercel-ai-sdk-6-deep-dive-features-tool-calls-2026)。
- **agent-loop 原语**：把多步「思考 → 调工具 → 再思考」的循环内置，补齐了过去要靠第三方框架才能做的能力[[Vercel AI SDK 6 Deep Dive]](https://www.digitalapplied.com/blog/vercel-ai-sdk-6-deep-dive-features-tool-calls-2026)。

### 最小心智模型（前端视角）

```ts
// 服务端：app/api/chat/route.ts
import { streamText, tool } from "ai";
import { openai } from "@ai-sdk/openai";
import { z } from "zod";

export async function POST(req: Request) {
  const { messages } = await req.json();

  const result = streamText({
    model: openai("gpt-5.5"),
    messages,
    tools: {
      getWeather: tool({
        description: "查询某城市天气",
        inputSchema: z.object({ city: z.string() }),
        execute: async ({ city }) => fetchWeather(city),
      }),
    },
  });

  return result.toUIMessageStreamResponse();
}
```

```tsx
// 客户端：组件中用 useChat 消费 message parts
"use client";
import { useChat } from "@ai-sdk/react";

export function Chat() {
  const { messages, sendMessage, status } = useChat();
  return (
    <div>
      {messages.map((m) => (
        <div key={m.id}>
          {m.parts.map((part, i) => {
            if (part.type === "text") return <p key={i}>{part.text}</p>;
            if (part.type === "tool-getWeather")
              return <WeatherCard key={i} data={part.output} />;
            return null;
          })}
        </div>
      ))}
    </div>
  );
}
```

> 要点：v6 之后，**渲染逻辑围绕 `parts` 展开**，工具调用结果可以直接映射到自定义组件，这是「生成式 UI」的工程基础。

## 三、React + AI 技术栈 2026（选型已收敛）

LLM 在生成 UI 时几乎总是选 React——不是因为 React 客观更优，而是训练语料里 React 占绝对多数；因此「会用 React + 配套栈」成为 AI 时代的基本盘[[The React + AI Stack for 2026]](https://www.builder.io/blog/react-ai-stack-2026)。本周梳理的一套主流默认栈：

| 层          | 推荐                              | 说明                                                                                                                   |
| ----------- | --------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| 核心        | React + TypeScript                | 类型给 AI 提供上下文，减少生成后返工[[Builder.io]](https://www.builder.io/blog/react-ai-stack-2026)                    |
| 框架        | Next.js / TanStack Start          | 要 RSC、流式选 Next.js；要更轻、更显式选 TanStack Start[[Builder.io]](https://www.builder.io/blog/react-ai-stack-2026) |
| 样式        | Tailwind CSS                      | AI 生成 class 极顺手[[Builder.io]](https://www.builder.io/blog/react-ai-stack-2026)                                    |
| 组件        | shadcn/ui                         | 代码进仓库、可被 AI 直接读改[[Builder.io]](https://www.builder.io/blog/react-ai-stack-2026)                            |
| 数据请求    | TanStack Query                    | 服务端状态、缓存、后台刷新[[Builder.io]](https://www.builder.io/blog/react-ai-stack-2026)                              |
| 状态        | Zustand                           | hook 式、低样板[[Builder.io]](https://www.builder.io/blog/react-ai-stack-2026)                                         |
| 表单/校验   | React Hook Form + Zod             | 性能好、生态广[[Builder.io]](https://www.builder.io/blog/react-ai-stack-2026)                                          |
| AI SDK      | Vercel AI SDK / TanStack AI       | AI Elements 提供 20+ 基于 shadcn/ui 的对话组件[[Builder.io]](https://www.builder.io/blog/react-ai-stack-2026)          |
| AI 辅助开发 | Builder.io / Claude Code / Cursor | 终端 / IDE / 可视化三种形态[[Builder.io]](https://www.builder.io/blog/react-ai-stack-2026)                             |

> 心智模型：**栈在收敛，差异化转移到「AI 接入能力」**——Chat/Agent UI、生成式 UI、RAG 接入、工具调用，才是当下值得投入的增量。

## 四、MCP 2026：Agent 工具调用的标准协议

Model Context Protocol（MCP）由 Anthropic 于 2024 年 11 月提出，现已成为连接 AI 与外部工具/数据的事实标准，被 OpenAI、Google DeepMind、Microsoft 采用；2025 年 12 月 Anthropic 将其捐给 Linux 基金会下的 Agentic AI Foundation，成为厂商中立、社区治理的标准[[Everything your team needs to know about MCP in 2026]](https://workos.com/blog/everything-your-team-needs-to-know-about-mcp-in-2026)。

### 核心模型（前端/Agent 视角）

- **三个角色**：Host（用户交互的 AI 应用）/ Client（管理与单个 server 的连接）/ Server（暴露能力）[[WorkOS]](https://workos.com/blog/everything-your-team-needs-to-know-about-mcp-in-2026)。
- **Server 三原语**：Tools（可执行的写操作，可被用户批准/拒绝）、Resources（可读数据）、Prompts（可复用模板）[[WorkOS]](https://workos.com/blog/everything-your-team-needs-to-know-about-mcp-in-2026)。
- **传输**：stdio（本地子进程）与 Streamable HTTP（远程 + SSE 流式），连接是有状态会话，便于多步操作[[WorkOS]](https://workos.com/blog/everything-your-team-needs-to-know-about-mcp-in-2026)。
- **N×M → N+M**：写一次 server，所有兼容 client 都能用，避免每个应用各写一套连接器[[WorkOS]](https://workos.com/blog/everything-your-team-needs-to-know-about-mcp-in-2026)。

### 本周新增能力（2026 规范方向）

- **Tasks（异步任务）**：「先调用、后取结果」，请求立即返回任务句柄，支持 working/input_required/completed/failed/cancelled 状态轮询或订阅[[WorkOS]](https://workos.com/blog/everything-your-team-needs-to-know-about-mcp-in-2026)。
- **Sampling**：server 可在执行中反向请求模型补全，并允许用户审阅/编辑后再回传，保持 human-in-the-loop[[WorkOS]](https://workos.com/blog/everything-your-team-needs-to-know-about-mcp-in-2026)。
- **Elicitation**：server 可暂停并向用户索取输入；URL 模式用于 OAuth、凭证录入、支付等必须在 client 外完成的安全交互[[WorkOS]](https://workos.com/blog/everything-your-team-needs-to-know-about-mcp-in-2026)。
- **MCP Apps（server 端渲染 UI）**：server 可下发交互式 HTML，由 host 在沙箱 iframe 中渲染，工具开始拥有「界面」而不止「返回值」[[The 2026-07-28 MCP Specification Release Candidate]](https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate)。
- **Tools 全面支持 JSON Schema 2020-12**，协议走向无状态化（stateless protocol, stateful applications），便于水平扩展[[MCP Release Candidate]](https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate)。

## 五、生成式 UI（Generative UI）

RSC 让 UI 可在服务端渲染并流式下发到客户端，配合 Server Actions，可让 LLM 直接从服务端生成并流式下发 React 组件——这是 AI 应用的新范式[[AI SDK RSC: Overview]](https://ai-sdk.dev/docs/ai-sdk-rsc/overview)。

> 注意：`@ai-sdk/rsc` 目前为实验性，Vercel 官方建议新项目优先使用稳定的 AI SDK UI（`useChat` + message parts），RSC 生成式 UI 暂停演进、有迁移指南[[AI SDK RSC: Overview]](https://ai-sdk.dev/docs/ai-sdk-rsc/overview)。落地选型上，**优先 message-parts 路线\*\*，把工具结果映射到组件来实现「生成式 UI」，比强依赖实验性 RSC 流更稳。
